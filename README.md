# Landingforyou

Портфолио с редактором в GitHub Pages и отдельной серверной версией.

Для запуска нужен Node.js 24 или новее. Дополнительные пакеты не требуются.

```sh
npm start
```

Сайт открывается по адресу http://127.0.0.1:4173, админка — http://127.0.0.1:4173/admin.

Учётная запись владельца настроена в локальной базе. Для создания или смены учётной записи запустите `npm run setup-admin` и введите логин и пароль. Пароль хранится в виде scrypt-хеша. Настройка учётной записи завершает действующие сеансы.

Команды запуска, настройки аккаунта и экспорта читают локальный `.env`, если он есть. За основу можно взять `.env.example`. Для первого запуска на новом сервере задайте `ADMIN_USERNAME`, `ADMIN_PASSWORD`, `DATA_DIR` и внешний `PUBLIC_ORIGIN`; существующие аккаунты при следующих запусках сохраняются. Значения пароля и сам `.env` не публикуются в Git.

В админке можно управлять всем содержимым страницы:

- «Блоки страницы»: добавлять текст, изображения, галереи и блоки с кнопками; менять заголовки, описания, порядок и видимость разделов; добавлять разделы в меню.
- «Проекты» и «Услуги»: создавать, редактировать, сортировать, публиковать и скрывать материалы. У проектов есть обложка, галерея с подписями, описание, задача, технологии и собственная кнопка со ссылкой.
- «Меню и ссылки»: менять подписи и адреса, добавлять внешние ссылки и менять порядок пунктов.
- «Тексты и контакты»: редактировать первый экран, название сайта, футер, текст обо мне, этапы работы, кнопки и форму заявки. Связь может вести в Telegram, на другой сайт, почту или телефон; допускаются `@имя`, `https://`, `http://`, `mailto:`, `tel:` и якоря `#раздел`.
- «Оформление» и «Медиатека»: менять логотип, цвета и видимость стикеров, загружать PNG/JPEG/WebP, выбирать изображения для любого блока и добавлять несколько фотографий в галереи.
- «Заявки»: читать обращения из формы сайта.

Кнопки публикации и сохранения записывают изменения в базу. Предпросмотр показывает текущие изменения, включая цвета, до сохранения. Если правка сделана во время сохранения, она остаётся в редакторе как несохранённая. Удаление требует подтверждения, а используемые в контенте изображения защищены от удаления. Старые базы получают новые поля автоматически без потери контента. Пароль серверного аккаунта и база в репозиторий не входят; при переносе аккаунт задаётся через `setup-admin` или переменные первого запуска.

SQLite хранится в `.local/portfolio.sqlite`. Сохраните всю папку `.local` при переносе сайта. Не добавляйте её в Git. `DATA_DIR` задаёт другой каталог для данных. Медиа и заявки также хранятся в базе.

Форма сохраняет заявки в админке. Уведомления через Telegram Bot API потребуют отдельного токена бота и настройки получателя. Прямая кнопка связи уже открывает диалог с владельцем в Telegram.

`HOST` и `PORT` управляют адресом сервера. По умолчанию он доступен только на этом компьютере. Для размещения на сервере с HTTPS задайте `PUBLIC_ORIGIN` равным внешнему адресу сайта. Эта настройка включает Secure для cookie сеанса.

`npm test` проверяет вход, защиту админки, публикацию, скрытие, предпросмотр, загрузку файлов, сохранение заявок, выход и сохранность данных после перезапуска на отдельной временной базе.

Исходники сайта находятся в `templates/site.html`, `public/site.css` и `public/site.js`. Сервер и работа с данными — в `src`. Ранее подготовленный файл `outputs/portfolio-extrafazant.html` теперь открывает рабочий локальный сайт.

## Бесплатная публикация на GitHub Pages

Рабочий сайт публикуется по адресу https://Cackeeev.github.io/landingforyou/.

Workflow Pages запускает проверки, собирает статические страницы и публикует их после изменений в main. Команда сборки — npm run build:pages. Для проекта в подпапке задайте PAGES_BASE_PATH=/landingforyou/.

GitHub Pages публикует и сайт, и отдельный редактор по адресу `/landingforyou/admin/`. Кнопка «Войти в админку» находится справа в футере. Для этого редактора не нужен сервер Node.js.

После входа можно менять блоки, проекты, меню, тексты, ссылки и изображения. Черновик и загруженные фотографии сохраняются зашифрованными в IndexedDB этого браузера; вкладка хранит ключ до выхода. «Сохранить изменения» сохраняет локальный черновик. Предпросмотр показывает текущие правки, а опубликованный сайт меняется только после отправки обновления в GitHub.

«Опубликовать в GitHub» запрашивает fine-grained токен с правом Contents: Read and write только к этому репозиторию. Токен используется в памяти для одной публикации и очищается из формы; он не хранится в черновике, sessionStorage или исходниках. Изменения `src/seed.json` и новых изображений отправляются одним коммитом в main. Проверяется версия контента и используется обновление ветки без force, чтобы не перезаписать чужие изменения. Затем обычный workflow Pages публикует сайт. Для скачивания без токена есть «Скачать обновление»: архив содержит обновлённый `src/seed.json` и изображения для загрузки в репозиторий.

Статическая страница редактора и его код публичны. Пароль разблокирует локальный редактор и его зашифрованные черновики; права публикации подтверждает токен GitHub. В `src/pages-auth.json` хранится только зашифрованная проверка пароля с PBKDF2 и случайной солью. Для смены данных входа задайте `PAGES_ADMIN_USERNAME` и `PAGES_ADMIN_PASSWORD` в приватном `.env`, выполните `npm run setup-pages-admin` и опубликуйте обновлённый файл настройки. Сам `.env` не добавляйте в Git.

Серверная версия по-прежнему доступна через `npm start`, использует отдельную SQLite-базу и серверные сеансы. Её встроенные заявки доступны при серверном размещении. Если нужен переход из Pages на такую админку, можно задать полный адрес в переменной репозитория `ADMIN_URL`; по умолчанию используется редактор прямо в Pages.

Для обновления контента опубликованного сайта внесите изменения в src/seed.json и отправьте их в main. Изменения локальной базы через админку хранятся на компьютере. Для переноса опубликованных материалов в Pages выполните npm run export:content и отправьте обновлённый src/seed.json и изображения в репозиторий. Черновики и скрытые материалы исключаются из экспорта.

Экспорт переносит логотип, обложки, галереи проектов и изображения новых блоков в статические файлы. Порядок разделов, меню, ссылки и цвета сохраняются. Черновики блоков и их изображения не добавляются в экспорт.

Файлы .local, work, outputs и .env исключены из Git. В репозитории хранится код серверной версии, но база, заявки и пароли туда не попадают.
